スマートフォンでは縦画面推奨です。起動後にカンパニー名を決め、グリダニアの小型物件から買収を始めてください。進行状況はブラウザへ自動保存されます。

## 1. ゲーム説明書

### 1.1 目的

プレイヤーは自分のカンパニーの「交易実務担当」です。タタルは商会長兼アドバイザーとして助言します。

グリダニアから開始し、都市内の「都市制覇対象」をすべて買収すると次の都市が解放されます。「任意の連合戦」は都市制覇数へ含まれません。次の順番で10都市すべてを制覇することが最終目標です。

1. グリダニア
2. リムサ・ロミンサ
3. ウルダハ
4. イシュガルド
5. クガネ
6. ラザハン
7. クリスタリウム
8. オールド・シャーレアン
9. トライヨラ
10. ソリューション・ナイン

キャラクター固有の長いストーリーやフィールド探索はありません。市場選択、買収戦、保有事業の管理がゲームの中心です。

#### FFXIV用語による組織と段階解放

本作では、FFXIVのパーティ／アライアンス／カンパニー／ギルドの用語を、交易ゲーム向けに次のようにアレンジします。公式設定上の組織そのものと、本作独自の交易組織を混同しないよう、ゲーム独自の名称には「交易」「トレード」を付けます。

- **タタル・カンパニー**: プレイヤーが運営する商会全体。FFXIV公式のフリーカンパニーやグランドカンパニーそのものではなく、本作独自の交易組織です。
- **トレード・パーティ**: 一回の買収戦へ参加する自社と傘下企業。傘下企業への個別資金要求は、最初の物件を取得した直後から利用できます。
- **ライトパーティ／LIMIT BREAK I**: 自社を含む4社がそろうと解放します。FFXIV公式でもLIMIT BREAKは4人以上のパーティで利用できるため、序盤から使える最初の到達目標とします。
- **フルパーティ／LIMIT BREAK II**: 自社を含む8社がそろった段階。より多くの傘下をまとめる中盤の総力出資です。
- **トレード・アライアンス**: 複数の商会・ギルド・カンパニーが一時的な共同戦線を組む、本作独自の大規模交易組織です。序盤から表示せず、ウルダハ制覇後にタタルの説明とともに解放します。FFXIV公式のアライアンスは3つのフルパーティ、最大24人で構成されます。
- **ギルド連携**: 木工、鍛冶、錬金、調理など、同じ専門分野の傘下を集めた事業シナジー。FFXIV公式のクラフター／ギャザラーと各ギルドの性格に対応させます。
- **グランドカンパニー**: FFXIV公式では都市国家が軍事・経済・技術を結集する統合司令部です。双蛇党、黒渦団、不滅隊は買収対象・所有物件・傘下企業にはならず、同時に1組織だけ許認可・調達・輸送の「公的後援」を申請できます。

段階解放の対象は、傘下企業への資金要求や4社LIMIT BREAKではなく、外部組織との提携、大規模なトレード・アライアンス、企業連合本部級の共同戦線です。新しい組織機能が解放されるたび、タタルのアイコンと短い説明セリフを表示します。

#### SYNERGYとBURST TIME

本作では、事業グループの成立だけでなく、味方側の有利効果が働いて商会の力が高まった状態を広く`SYNERGY`と呼びます。

- 味方へ追い風が吹き、資金投入効果が上昇する
- トレード・パーティの参加企業が増え、総力出資が強化される
- 同業種や同地域の企業がそろい、ギルド連携・地域連携が成立する
- 外部カンパニーやトレード・アライアンスの支援が加わる

これらの条件が初めて成立したときは、タタルのアイコンとともに「SYNERGY発動！」を表示します。味方への追い風と、パーティ／ギルド／地域などの味方シナジーが同時に有効な時間は`BURST TIME`と呼びます。BURST TIME中は青を基調に金色を加えた専用演出で、通常の有利状態より強い好機であることを明確に伝えます。敵側だけに追い風が吹いている状態はBURST TIMEには含めず、赤い警告演出で区別します。

公式用語の根拠:

- [リミットブレイクの使い方](https://jp.finalfantasyxiv.com/uiguide/battle/battle-lb/uiguide_lb_how.html)
- [フリーカンパニーとは](https://jp.finalfantasyxiv.com/lodestone/special/grandcompany/about_freecompany/)
- [グランドカンパニー](https://jp.finalfantasyxiv.com/lodestone/special/grandcompany/)
- [フロントライン：アライアンス構成](https://jp.finalfantasyxiv.com/lodestone/playguide/contentsguide/frontline/)
- [クラフター・ギャザラーガイド](https://jp.finalfantasyxiv.com/crafting_gathering_guide/)

### 1.2 最初にすること

1. 起動演出の最後でカンパニー名を入力します。
2. 最初はグリダニアの買収対象が表示されます。
3. 買収したい物件を選びます。
4. 相場の3%にあたる仲介手数料を払って買収戦を開始します。
5. ギルを積み、所有率を100%まで押し切ります。

デフォルトのカンパニー名は「タタルの大繁盛商店」です。カンパニー名、所持金、物件、装備スキル、外部協力／公的後援、解放説明の既読状態はブラウザの`localStorage`へ自動保存されます。

### 1.3 基本ループ

1. 市場で物件・現在相場・都市進捗を見る
2. 買収戦で自社資金や支援資金を積む
3. 物件を取得して毎秒収益を増やす
4. 同業界・同地域・事業グループのボーナスを作る
5. 都市を制覇して次の都市を解放する
6. 強力な企業連合本部へ挑む

### 1.4 主要画面

| 画面 | 役割 |
| --- | --- |
| 市場 | 都市マップ、買収対象、相場、風向き、地域制覇状況 |
| 保有資産 | 所有物件、収益、独立危険度、ネマワシ |
| スキル | 買収戦へ持ち込む「かけひき」の装備 |
| 企業連合 | 企業連合本部、参加組織、同盟 |
| 買収戦 | ギルの積み合い、所有率、敵予算、資金コマンド |

市場の「はじめての方へ」、各所の「？」、買収戦右上のヘルプからゲーム内説明も確認できます。戦局ログは初期状態では閉じています。

## 2. 買収戦のルール

### 2.0 開始前ブリーフィングと時間制御

買収対象を選ぶと、まず`BUYOUT DUTY`が開きます。自社名、敵企業名、都市・業界、相場、仲介手数料、今回有効な`SYNERGY`と`TRADE PARTY`を確認できます。「効果を確認して討滅戦開始」を押すまで、所有率、敵AI、COMMAND、スキル、風は進みません。開始時は「対象社名 討滅戦 START!」を全画面表示します。

- 自社資金タブ: 通常速度。商流回復も100%速度
- 資金源・かけひきの選択中: `TACTICAL MODE ×0.1`。商流回復も通常の10%速度。どのコマンドも1回実行すると自社資金タブへ戻り、通常速度へ復帰
- ブリーフィング、SHORT、LBチャージ、決着確認、リザルト、ヘルプ、ログ: 完全停止。100%直前の決着演出だけ`DECISIVE SLOW ×0.16`

### 2.1 戦闘中の商流回復

買収戦中は、店舗収益や売掛金の回収を表す「商流回復」により、可処分資金が少しずつ戻ります。一気に100%へ戻る効果ではありません。

- 通常時: 対象相場の約0.3%／秒
- 資金源・かけひき・LB選択中: 通常速度の10%
- 1戦の回復上限: 対象相場の15%
- 回復分は戦闘内でだけ使える回転資金で、撤退を繰り返して所持金を稼ぐことはできない

双方が資金を使い切った場合でも、数秒待てば最小投入分を再確保できるため、敵をSHORTさせた後のFINAL PUSHが可能です。

### 2.2 勝敗

- 自社所有率100%で勝利
- 自社所有率0%で敗北
- 撤退ボタンを押すと敗北扱い
- 敵の追加防衛資金が0になった状態を`SHORT`と呼ぶ
- `SHORT`になっただけでは自動勝利しない
- `SHORT`になった瞬間は盤面を残したテロップで約1.2秒停止し、その後は直前の時間倍率で自動再開する
- `SHORT`後に自社資金を直接投入すると`FINAL PUSH`が発生する
- `SHORT`後、既存の資金差だけで100%へ届いた場合は`CAPITAL PRESSURE`で勝利する
- `LIMIT BREAK`で100%へ届いた場合はFINAL PUSHを経ず決着の一撃演出へ入る
- 100%／0%へ到達する直前は0.76秒の`DECISIVE BLOW`を挟み、最後の一撃だけスローに見せる。勝敗直後はWIN/LOSEテロップ後も最終盤面で停止し、画面下の`NEXT →`を押してからタタルの分析へ進む

FINAL PUSHは「敵の資金切れを確認してから自分でとどめを刺す」ための仕様です。決着判定ではクランプ前の生所有率を保存します。

### 2.3 所有率ゲージ

内部ゲージ`G`は`-100`から`+100`です。

- `-100`: プレイヤー勝利
- `0`: 拮抗
- `+100`: 競合勝利

画面上の自社所有率は次の式です。

```text
自社所有率 = (100 - G) / 2
```

基本速度は`src/utils/formatter.ts`の`calculateGaugeVelocity()`で計算します。

```text
差額 = 自社有効投資額 - 敵有効投資額
速度 = 線形項 + 対数項
```

自社と敵がこれまで積んだ累計額の差が、所有率を連続的に動かします。ボタンを押した瞬間の小さな衝撃に加え、その後も資金差に応じてゲージが動き続けます。

### 2.4 自社資金

買収戦開始時の可処分資金は、ゲーム全体の所持金から仲介手数料を除いた額です。画面左側に残額と残り％を表示します。

| 投資段階 | 対象相場に対する投入額 |
| --- | ---: |
| 小口 | 2% |
| 堅実 | 5% |
| 強気 | 10% |
| 大口 | 20% |
| 全力 | 35% |

選択中の投資額を払えなくなった場合は、購入可能な最大段階へ自動的に下がります。払えない段階のボタンは無効になります。

### 2.5 敵の防衛資金

敵の総予算は買収開始時に固定され、無限には増えません。

```text
敵総予算 =
  現在相場
  × 物件価格帯係数
  × 企業連合本部補正
  × 業界・地域による防衛割引
  × 敵バランス補正
```

敵バランス補正はチュートリアル`×1.08`、グリダニア`×1.30`、リムサ`×1.42`、ウルダハ以降の通常戦`×1.55`、ゴールドソーサー`×1.72`、企業連合本部`×1.75`です。

- 開始時に総予算の25%を先に積む
- 残り75%が追加防衛資金
- 敵AIは所有率、風、風の残り時間、資金差、プレイヤーの直前行動を見て、投入・温存・風待ち・緊急防衛を判断
- 残予算0で`SHORT`
- すでに積んだ敵資金は`SHORT`後も消えない

敵側のコイン領域に、追加防衛資金を99.9%から0%まで表示します。

### 2.6 風とBURST

風は市場だけの飾りではなく、買収戦の計算へ実際に入ります。8秒ごとに変化します。

| 風 | 実効果 | バトル演出 |
| --- | --- | --- |
| 自社追い風 | 自社有効投資額×1.35 | 青い全画面告知。味方SYNERGYも有効なら青＋金の`BURST TIME` |
| 自社向かい風 | 自社有効投資額×0.72 | 赤い防衛圧・盤面警告 |
| 競合追い風 | 敵有効投資額×1.35 | 赤い全画面警告と強い流線 |
| 乱旋風 | 双方×1.12、ゲージ速度×1.45 | 黄色い高速乱旋風 |
| 静穏 | 補正なし | 青い静穏表示 |

風が変わるたび、画面中央へ効果倍率を全画面告知し、所有率ゲージ上の継続表示、魔法エフェクト、戦局ログも更新します。グループ資金や外部パーティ支援の実行時は`SYNERGY発動！`、味方追い風と重なれば`BURST TIME`を表示します。

### 2.7 支援資金

#### 個別の傘下企業

- 対象企業の相場45%を支援額として追加
- 要求ごとに独立危険度+18
- 同じ交渉中でも繰り返し要求可能
- 独立した場合、その企業が過去に積んだ支援額も失う

#### 事業グループ

- 条件を満たした複数社へ一括要求
- 各社の相場34%を基礎に、グループ連携×1.28
- 各社の独立危険度+14

#### 外部協力・公的後援

- 同時に有効にできる協力先は1つ
- ガーロンド・アイアンワークスは企業協力。不可侵契約があり、協定企業の所有物件へ挑むと解除
- 双蛇党・黒渦団・不滅隊は公的後援。買収・所有・傘下化せず、通常物件への挑戦で自動解除されない
- 一交渉につき1回、対象相場の32%相当を支援
- GC後援は許認可・調達・輸送を含む「支援価値」として扱い、所有物件数・収益・SYNERGY・独立危険度・LB企業数には含めない

#### LIMIT BREAK

自社と傘下企業による、一交渉一回の全社一斉出資です。ALLIANCEは企業数にも投入額にも含みません。

| 自社を含む企業数 | 段階 | 倍率 |
| ---: | --- | ---: |
| 1～3社 | 未解放 | 使用不可 |
| 4～7社 | LIMIT BREAK I | ×1.44 |
| 8～15社 | LIMIT BREAK II | ×1.80 |
| 16社以上 | LIMIT BREAK III | ×2.22 |

```text
LB基準額 = 対象相場の28%（自社枠）+ 独立しなかった全傘下の各社相場28%
LB最終投入額 = LB基準額 × 段階倍率
```

- 攻防の資金衝突によるゲージ蓄積は従来比×1.20
- 発動時の全社動員資金は従来比×1.20（上表の倍率へ反映済み）
- 直接所有率上昇の安全上限はLB I / II / IIIで10 / 20 / 30ポイント
- 未使用ゲージは次戦へ持ち越し、最大時はAETHER OVERFLOW演出を表示
- 各社の独立危険度+12
- 企業ごとに独立判定し、離反企業は今回のLBへ参加しない
- 離反すると、その会社が過去に積んだ支援額も失う
- 約1.85秒の溜め中は通常進行を停止
- 適用後の生所有率が100%以上ならFINAL PUSHなしで直接勝利
- 100%未満なら敵へ緊急防衛出資を強制し、残予算を使い切ればSHORTへ移行
- それでも未決着なら戦闘を続行

強力ですが、どの敵も必ず一撃で倒す即死技ではありません。

### 2.8 決着方法とOVERKILL

決着方法は`FinishMethod`として戦闘結果へ保存されます。

- `LIMIT BREAK I / II / III`
- `FINAL PUSH`
- `CAPITAL PRESSURE`
- `NORMAL BUYOUT`

```text
生所有率 = (100 - 生ゲージ値) / 2
OVERKILL = max(0, 生所有率 - 100)
```

OVERKILLは勝ち方の派手さを表し、資金効率の優劣ではありません。0～4.9%は「精密交渉」、5～19.9%は「決定的優勢」、20～49.9%は「圧倒的買収」、50%以上は「過剰制圧」です。

### 2.9 独立危険度

独立確率は`src/utils/formatter.ts`の`calculateRebellionProbability()`で計算します。

```text
P = 1 / (1 + exp(-0.1 × (危険度 - 60)))
```

危険度10以下では独立確率を0に固定しています。ネマワシやポートフォリオの管理で危険度を下げられます。

買収戦中に独立した物件は、戦闘結果確定時に独立物件へ戻り、その物件の現在評価額が強制清算金として自社へ戻ります。

### 2.10 費用と報酬

- 仲介手数料: 対象相場の3%。勝敗・撤退に関係なく支出
- 自社直接出資の確定費用:
  - 勝利時: 投入額の35%
  - 敗北・撤退時: 投入額の75%
- 勝利時運転資金: 対象相場の5%
- 取得物件の`annualRevenue`: 実装上は「毎秒収益」
- 支援資金は直接出資の確定費用へ含めない

### 2.11 業界・地域・交易網ボーナス

#### 業界影響力

| 条件 | 表示 | 効果 |
| --- | --- | --- |
| 2件保有かつ40%未満 | 顔が利く | 表示のみ |
| 3件以上または40%以上 | 影響力 | 自社押込+5% |
| 過半数 | 業界掌握 | 自社押込+10%、敵予算-10% |

#### 地域影響力

| 条件 | 表示 | 効果 |
| --- | --- | --- |
| 1件以上 | 足場を築いた | 自社押込+3% |
| 半数以上 | 地域優勢 | 自社押込+8%、敵予算-5% |
| 都市制覇 | 地域制覇 | 自社押込+12%、敵予算-8% |

都市制覇1件ごとに交易網補正+2%。最大+16%です。

### 2.12 かけひき

| スキル | 実装上の効果 |
| --- | --- |
| 神速魔 | 10秒間、命令ゲージ進行を約1.8倍（再使用18秒） |
| 士気高揚の策 | 買収戦に参加中の全傘下の独立危険度を半減 |
| 連環計 | 9秒間、敵追加防衛を70%で中断し、既投入額を相場12%まで崩す |
| 消沈 | 9秒間、敵の追加防衛間隔を1.6倍へ延長 |
| 意気衝天 | 一交渉1回、対象相場の30%を無料支援資金へ追加 |
| リビングデッド | 総資産100万ギルで解放。一交渉1回、10秒の待機中に所有率0%へ到達すると1%で耐え、次の10秒で正規化所有率30%以上へ戻せなければ敗北 |
| バトルリタニー | 7秒間、所有率の押し込み速度×1.5 |

スキルの名称、解放条件、説明文は`src/data/initialData.ts`にあります。物件・業界・総資産・SYNERGYの修得条件は装備画面と戦闘の両方へ適用されます。効果の実処理は`BattleModal.tsx`の`useSkill()`です。旧セーブ互換のためリビングデッドは旧`skill_sns_blitz` IDを維持します。

戦闘中は`SPECIAL ACTIONS`欄から装備スキルとLBを1タップで実行できます。従来の詳細パネルも残し、実行後は自社資金パネルと通常速度へ戻ります。味方と敵のアクション待ちは、同じ幅の秒表示＋進行バーで比較できます。

### 2.13 セーブについて

セーブは`localStorage`へスキーマバージョン3として自動保存されます。

- 保存される: カンパニー名、所持金、物件の所有・独立危険度、装備スキル、外部協力／公的後援、解放説明の既読ID、保存時刻
- 保存されない: 戦闘途中、風、市場の一時変動、COMMAND、戦闘内クールダウン

有効なセーブがあれば起動演出を飛ばして自動ロードします。復帰時は現在の毎秒収益を基準に最大30分分のオフライン収益を加算します。ヘッダーの回転矢印から確認後にセーブを削除できます。

## 3. ロマサガ3トレードとの違い・難易度設計・Codex所感

### 3.1 原作から受け継いでいる核

このゲームは『ロマンシング サ・ガ3』のトレードを完全再現したものではありません。原作のキャラクター展開やイベント進行ではなく、次のゲームループをFF14風の題材へ移植した作品です。

- 物件を買収して傘下を増やし、より大きな相手へ挑む
- 自社資金だけでなく、傘下企業や事業グループから資金を集める
- 資金量の差によって、リアルタイムに買収の優勢・劣勢が動く
- 強い資金要求には物件独立の危険が伴う
- 士気高揚の策や神速魔などの「かけひき」で資金戦を有利にする
- 特定の物件の組み合わせを集め、グループ資金を主力に育てる

原作でも、物件から集めた資金とグループボーナス、かけひき技、独立危険度の管理が買収劇の中心です。本作も「大金を持つこと」だけでなく、「どこから、いつ、どれだけ調達するか」を中心にしています。

### 3.2 実際の実装が原作と異なるところ

| 項目 | ロマサガ3トレード | 現在の本作 |
| --- | --- | --- |
| 進行 | 3段階のトレードイベントと目標企業・組織の買収 | グリダニアから10都市を順番に制覇するキャンペーン |
| 世界・物件 | ロマサガ3の町、会社、産業グループ | FF14主要都市、ショップ、組織、産業を題材に再構成 |
| 買収の見せ方 | 一本の買収ゲージと資金要求を一画面で処理 | 所有率ゲージ、両陣営の資金残量、積み上げコイン、風、ドットキャラを同一戦闘画面に表示 |
| 自社資金 | 総資産から支出するかけひきも含む | 戦闘開始時に使用可能資金を確定し、相場比2～35%の段階投入 |
| 敵資金 | 相手物件ごとの内部パラメータとAI行動 | 相場・価格帯・企業連合本部・影響力から予算を算出し、25%を初期投入、残り75%を判断型AIが追加・温存 |
| 資金切れ | 資金競争の結果としてゲージで決着 | 敵が`SHORT`しても即勝利せず、次の自社資金投入による`FINAL PUSH`で決着 |
| グループ技 | 所有物件の組み合わせから発生し、主要な資金源になる | 事業グループ、個別傘下、同盟、全社投入`LIMIT BREAK`に分割 |
| 独立 | 資金要求やグループ技の重要なリスク | 確率式を画面上の危険度として可視化。独立すると、その会社から積んだ過去支援額も崩落 |
| かけひき | 習得条件や対象相性を持つ多数の技 | 7スキルに整理し、クールダウン制、敵妨害、即時資金、速度強化として実装 |
| 時間変化 | コマンド待ち時間とゲージ速度・加速度 | コマンドゲージ、敵AI間隔、微動・急変、5種類の風による倍率変化 |
| 成長 | 物件価値やグループ形成を利用してイベント目標を達成 | 所有物件の収益、業界影響力、地域影響力、都市制覇による交易網補正を累積 |
| セーブ | RPG本編のセーブデータ内で進行 | `localStorage`へ攻略状態を自動保存し、最大30分のオフライン収益を回収 |

特に大きい違いは`SHORT → FINAL PUSH`です。これは原作の厳密な再現ではなく、「敵の予算切れを確認したうえで、最後に自分のギルで押し切った」とプレイヤーが理解できるよう追加した独自ルールです。

また、本作の「風」は原作のかけひき技「時代の風」をそのまま再現したものではありません。戦況へ常時変化を与え、同じ資金差でも投入のタイミングを変えるための独自の市場コンディションです。

### 3.3 現在の難易度を決めている基準

難易度は反射神経より、次の3つを理解して遊ぶ基準に設定しています。

1. **資金効率**
   自社資金を連打すれば短期的には強い一方、勝利後も資金を残さなければ次の物件へ進めません。安い物件から傘下を作り、支援資金を増やすほど有利になります。
2. **投入タイミング**
   敵の残予算、所有率の移動、風、コマンド回復を見て投入します。敵が資金を追加した直後、追い風中、または`SHORT`後のとどめが主な判断点です。
3. **傘下リスク管理**
   個別要求、グループ要求、`LIMIT BREAK`は手元資金を減らさず大きく押せますが、独立危険度が上がります。士気高揚の策を挟むか、危険を承知で一斉投入するかが中盤以降の賭けになります。

敵予算は価格帯別基礎値に、チュートリアル1.08、グリダニア1.30、リムサ1.42、ウルダハ1.55、ゴールドソーサー1.72、企業連合本部1.75の段階補正を掛けます。敵は25%を初期投入し、残り75%は風・所有率・資金差・直前行動・都市段階に応じて積むか温存します。したがって、単に相場と同額の現金を持っているだけでは安定勝利になりません。

想定している標準的な遊び方は次の通りです。

- 序盤: 小型物件を自社資金中心で取得し、操作と`FINAL PUSH`を覚える
- 中盤: 同業・同地域の物件を揃え、個別支援と事業グループを主力にする
- 終盤: 敵予算を影響力で削り、士気高揚の策、妨害スキル、風、`LIMIT BREAK`を組み合わせて大型物件を崩す

通常キャンペーンの基準相場は、グリダニアの2K～15Kからトライヨラの6.5Mまで段階的に上昇します。ゴールドソーサーはウルダハ内の例外的な強敵で、その直後のイシュガルドは一度立て直せる価格帯です。東アルデナード商会と一部の知識・技術交易連盟は「任意の連合戦」として都市解放条件から外れますが、最終都市ソリューション・ナインの参加組織2件は都市制覇対象です。

このため、最初から高額物件へ正面攻撃する遊び方は難しく、安い物件から買収網を組み立てる遊び方を標準としています。逆に、資金源と影響力を十分に育てれば、後半は「蓄えた経済圏を一斉に動かす」強さを実感できる設計です。

### 3.4 Codexとしての所感

現在の実装は、ロマサガ3トレードの**完全再現ではなく、核を借りたリアルタイム資金バトル**です。資金源を増やす喜び、グループ技で桁の違う金を動かす快感、独立を恐れながら資金を求める緊張感は、かなり原作の方向へ近づいています。とくに、敵予算の可視化、積み上がるコイン、`SHORT`後の`FINAL PUSH`は「何に勝ったのか」を本作独自の方法で伝えられています。

一方で、原作ほど完成していないのは**長期の経済設計と、選択肢ごとの個性**です。現在は個別傘下、事業グループ、`LIMIT BREAK`の多くが「投入額と独立リスクの違い」に集約されており、十分な傘下を得た後は強い資金源を順番に押すのが正解になりやすいです。原作にあった、物件の組み合わせを探す面白さ、技の効きやすい相手を見抜く面白さ、限られた経済圏で攻略手順を考える余地は、まだ拡張できます。

敵AIは都市段階に応じて賢くなり、優勢時の無駄な追随を止め、小口の囮を見送り、プレイヤー追い風の終了を待ち、大口やLBだけへ素早く反応します。特にゴールドソーサーは序盤の最初の強敵です。自滅待ちは完全に禁止していませんが、風と投入額を読んで敵の予備資金を吐かせる準備が必要になりました。

完成度を一段上げるなら、敵の数値を単純に増やすよりも、次の方向が合っています。

- 物件ごとに「小口へ強い」「大口投入後に反撃」「特定業界の資金を崩す」などの防衛個性を付ける
- グループごとに調達速度、上限、独立しやすさ、風との相性を変える
- 勝利時の残金、独立ゼロ、短時間決着などを評価し、上手い勝ち方を可視化する
- 都市ごとに推奨資金帯を示し、易しさではなく準備不足の理由を伝える
- 攻略状態を保存し、10都市制覇を一続きの経営判断として成立させる

Codexの評価では、現版は「ギルを積んで押し合う瞬間」はゲームになっています。次の課題は、勝敗の前後をつなぐ経営判断を厚くし、**同じ勝利でも、どの資金網を作り、どのリスクを取ったかによって手触りが変わるゲーム**へ育てることです。

### 4.5 買収開始から精算まで

1. `MarketView.handleBuyoutClick()`が変動後の現在相場を`Property.marketPrice`へ入れる
2. `App.handleStartBuyout()`が都市解放を確認し、`activeBattleProperty`へ設定
3. `BattleModal`が仲介手数料、敵予算、戦闘内残高を初期化
4. 戦闘中は`BattleModal`内だけで投資・AI・ゲージを管理
5. `confirmResult()`が精算値を`App.handleBattleEnd()`へ返す
6. `App`が所持金、所有権、独立、都市解放を確定

リザルトが出た時点ではまだ全体状態へ反映しません。「買収結果を確定する」を押した時に`onBattleEnd()`が走ります。

### 4.6 市場価格

`MarketView`は物件ごとに表示用の`marketRates`を持ちます。

- 初期変動: 基準価格の-10%から+10%
- 4秒ごとにランダムな1物件を最大-15%から+25%の範囲で更新
- 買収開始時、その表示価格を`targetProperty.marketPrice`として戦闘へ渡す

この価格変動は市場画面のローカルstateであり、`INITIAL_PROPERTIES`自体を書き換えません。

### 4.8 画像・音声の方針

- キャラクター、ジョブアイコン、背景は公式FF14ファンキット素材だけを使用
- 資金チップはユーザー提供のギル硬貨画像を透過・縮小・色調整したPNGを使用
- 新しい画像を追加するときは出典と利用条件を確認
- 第三者サイトから拾った画像やゲーム画面の無断切り抜きを追加しない
- 討滅戦開始、機能解放、LIMIT BREAK、勝敗は公式ファンキットの着信音SEを優先。読み込み／自動再生失敗時だけ`src/utils/audio.ts`のWeb Audio合成音へフォールバック
- 公式配布外のFF楽曲や音源は追加しない。決着の打撃音や資金投入音はプロジェクト独自の合成音

### 4.9 現在の既知仕様・注意点

- 攻略状態は`localStorage`保存。別端末・別ブラウザには同期しない
- `annualRevenue`という名前だが、ゲーム上は毎秒加算し、実収益は一括定数で2倍
- 戦闘開始後にApp側で増えた毎秒収益は、戦闘内`cash`へ同期しない
- 風は8秒ごとのランダム選択。都市・業界による出現率補正は未実装
- 戦闘内支援額は「借入金」ではなく、精算コストなしの支援戦力として扱う
- `UPDATE`には未実装案と実装済み案が混在
- `public/game/`は生成物だが、Sitesから配信するためGit追跡対象

### 4.10 改修時のチェックリスト

1. ルール変更ならゲーム内ヘルプとREADMEも更新する
2. 勝利条件を変える場合、通常ゲージ勝利とFINAL PUSHの両方を確認する
3. 資金コマンドを変える場合、表示額、実投入額、独立崩落額、リザルト分析を揃える
4. 市場と戦闘で同じ風オブジェクトが渡っていることを確認する
5. 360px前後のスマホ幅で、コマンドと下端余白を確認する
6. `pnpm run lint`
7. `pnpm run check:balance`
8. `pnpm run build`
9. `public/game/`のハッシュ付きJS/CSSと`index.html`を一緒にコミットする
10. Sitesでは`.openai/hosting.json`の既存`project_id`を必ず再利用する
11. 非公開アクセスを確認してから非公開デプロイする

## 5. 開発・起動

### 必要環境

- Node.js 22.13以上
- pnpm

### インストール

```bash
pnpm install
```

### ローカル開発

Sitesラッパーを含む開発サーバー:

```bash
pnpm run dev
```

ゲーム単体:

```bash
pnpm run dev:game
```

Windowsでは`start-game.bat`からゲーム単体の開発サーバーを起動できます。

### 検査

```bash
pnpm run lint
pnpm run check:balance
```

`lint`の実体は`tsc --noEmit`による型検査です。`check:balance`は都市別価格・収益、都市制覇対象、敵AIの代表判断、スキル解放、LIMIT BREAK実額を決定論的に検査します。

### 本番ビルド

```bash
pnpm run build
```

ビルドは二段階です。

1. Viteゲームを`public/game/`へ生成
2. vinext/Sitesラッパーを`dist/`へ生成

`app/page.tsx`は`/game/index.html`をiframeで表示します。`app/layout.tsx`はOGPを含むSites側メタデータを担当します。

## 6. Sites公開構成

| 場所 | 役割 |
| --- | --- |
| `.openai/hosting.json` | 既存SitesプロジェクトIDとバインディング |
| `app/` | Sitesで表示するNext/vinextラッパー |
| `worker/index.ts` | vinextのCloudflare Workerエントリ |
| `build/sites-vite-plugin.ts` | ビルド時にhosting設定を`dist/.openai/`へコピー |
| `vite.config.ts` | vinext、Cloudflare、Sitesプラグイン |
| `vite.game.config.ts` | iframe内ゲームのVite設定 |
| `public/game/` | Git追跡するゲーム本番アセット |
| `dist/` | Sitesへ渡す再生成可能な最終ビルド |

既存サイトを更新するときは、新しいSitesプロジェクトを作らないでください。`.openai/hosting.json`の`project_id`をそのまま使います。

## 7. フォルダ管理

### Git追跡するもの

- `src/`
- `app/`
- `worker/`
- `build/`
- `public/ff14-fankit/`
- `public/game/`
- `.openai/hosting.json`

### 再生成可能・Git追跡しないもの

- `node_modules/`: 依存パッケージ
- `dist/`: Sites本番ビルド
- `.wrangler/`: Cloudflare/Wranglerの一時状態
- `tmp/`: 作業アーカイブやPDF処理の一時ファイル
- `coverage/`: テストカバレッジ
- `*.log`: ログ
- `tsconfig.tsbuildinfo`: TypeScriptの一時情報

ローカルに置かれた調査PDFはデータ作成の参考資料です。`.gitignore`の`*.pdf`によりGitへは入りませんが、バックアップや一時ファイルではないため自動削除対象にしません。
