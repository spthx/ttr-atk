## 原作から直接確認できる不変要素

### コイン

**観測**

- 第1部の少量は、厚い台の中央に置かれた低い複数束として始まる。安定状態で薄い1枚を空中へ残さない。落下途中の束が一時的に空中へ見えること自体は禁止しない。
- 基本形は前後に段差を持つ円形／台形の山。前列が低く、中央・後列が高い。
- 各束は上面の楕円と縦の胴を持ち、胴には1枚単位の水平線が通る。
- 後半は束の本数だけでなく柱の高さが大きく増え、画面の縦方向を占有する。
- 左右は同じ描画語彙を使う。陣営差は色帯・名称・資金量で示し、台やコインの物理法則は変えない。

**計測**

- SFC序盤フレームでは、各台がおおむねゲーム映像幅の約35〜38%を占める。
- リマスター序盤では、各台がおおむねゲーム映像幅の約29〜32%を占める。
- 序盤の完成山は、おおむね4前後の奥行き列と18前後の横位置で構成されて見える。圧縮映像のため厳密なスプライト数ではない。

**推測**

- 原作は金額を1枚ずつ線形対応させず、固定の束／列を段階的に増やすことで少量から可読性を確保している。
- 後半は同じ基本束を再利用し、柱の高さと画面外からの追加でインフレ感を作っている。

### 台

**観測**

- 空の状態でも、楕円の上面と厚い前面を持つ円柱状の台として見える。線だけの皿ではない。
- 前面はコイン最下部を隠す。最前列の束は台の上面／前縁へ食い込み、接地しているように見える。
- 前縁には縦の刻みまたは素材の筋があり、奥行きと重量を補強する。
- 完成山が巨大になると台は多くを隠されるが、柱の基部は画面下端／台へ連続し、空中には浮かない。

**推測**

- 接地感の主因は影よりも、描画順による前縁の遮蔽と、台の十分な厚みである。

### アニメーション

**観測**

- 資金は上方から複数束で降り、既存の完成山へ追加される。
- コマンド窓、解決テキスト、別陣営の投入が出ても、完成済みの山は保持される。
- 完成山が消えるのは、資金0や商戦終了など意味のある状態遷移である。
- 後半ほど上方の降下束と下方の完成柱が同時に見え、投入規模を一目で理解できる。

**未確認**

- YouTubeの30/60fps変換・シーク誤差・編集を含むため、SFC原版の1束あたり正確なフレーム数は今回の資料から断定しない。
- 映像内の実況・BGM・再圧縮が混在するため、効果音の原音・音量・正確な同期値は別の直接収録で監査する。

### ゲーム展開・コマンド・攻防テンポ

**観測**

- 序盤映像の主コマンドは「資金を要求する」「グループに要求」「自社資金を出す」。後半では「かけひきをする」「同盟からの資金」も加わる。
- プレイヤーはコマンドを選び、その結果としてまとまった資金搬入が解決される。資金搬入中も背景の押し合いと既存山は読める。
- 序盤は低い山の範囲で数回の要求を重ね、後半は大口グループ／同盟で巨大な柱を作る。序盤から巨大柱にしないことが、後半のインフレ感を成立させる。
- 敗北側が0になるとその側だけ台が空になる。正の資金を持つ側まで同時に空にしない。

**補助資料から確認**

- 買収は左右の背景バーを押し切る資金競争で、資金源は個別企業、グループ、自社資金、スキルに分かれる。
- 企業／グループからの資金は搬入に時間がかかり、自社資金は即時性が高い。この差が「要求先を選ぶ→搬入を待つ→次の指示」という攻防テンポを作る。
- 原作の進行は3ミッションで、第1部は総資産1億、第2部はドフォーレ商会、第3部はアビスリーグが大目標になる。各部の中でも積載量は低負荷から高負荷まで変わるため、「部」と「山の高さ」を同義にしない。

**推測**

- 現行版のリアルタイム再充填は原作の完全同型ではない。原作らしさを保つには、操作受付中・コマンド解決中・資金搬入中を視覚的に区別し、搬入中も次に読むべき情報を消さないことが重要。

## 自動回帰へ落とす数値・不変条件

### P0: 接地と連続性

1. **非浮遊**: settledコインの各連結成分は、同じ山の別コインまたは台上面／前縁マスクと接触する。DPR 1で1 CSS px以上の完全な背景隙間を許さない。
2. **前縁遮蔽**: 最前列コインの下端は、台前面に少なくとも`max(1 CSS px, 0.10 * coinBodyHeight)`隠される。
3. **台の常在**: 商戦中、左右の台ピクセル領域は資金0でも存在する。画面外へ移動しない。
4. **完成山保持**: 正の投入、コマンド表示、AI投入、rack/page移送中に、直前フレームの完成山面積が0にならない。
5. **正の投入の面積連続**: 明示的なbank移送を除き、隣接33msフレーム間のsettled金色面積減少を15%以下とする。bank移送時もbanked+active合計は15%超減らさない。
6. **意味のある消失**: 山の完全消失を許すのは、当該陣営の表示資金0、商戦終了、または画面離脱だけ。

### P1: 原作の台・量感

7. **台の前面厚**: 台の見かけ前面高を、各required viewportで最低3 CSS px、かつ`0.45 * coinBodyHeight`以上にする。
8. **wide占有率**: 1440x900の商戦フィールドで、各台幅をフィールド幅の24〜32%にする。最低24%未満を失敗とする。
9. **低背横持ち占有率**: 844x390で各台幅をフィールド幅の20%以上にする。現在の約14〜15%は不合格。
10. **左右対称**: 同額・同状態の左右台の中心、幅、高さ、前縁位置の差を1 CSS px以内にする。人物は計測マスクから外し、別途遮蔽率を測る。
11. **人物遮蔽率**: 操作受付中、人物が台＋settledコインの可視面積を隠す割合を各側15%以下にする。接地部の遮蔽は0%を目標とする。
12. **外周安全域**: settled山と台はキャンバス内へ2 CSS px以上の余白を持つ。降下中だけ上端からの進入を許可する。

### P1: 序盤→後半の段階差

13. **少量形**: 最初の非0状態は中央寄せの複数束または低い複数枚で開始し、孤立した1枚／1束を台から離して置かない。
14. **三段階識別**: 同じviewportの少量・中量・多量スナップショットで、山の高さまたは可視金色面積を隣接段階ごとに15%以上増やす。上限到達後はbanked柱の高さまたは台下降量で差を示す。
15. **後半縦成長**: full-page/banked状態では、少量時より山＋柱のバウンディングボックス高を50%以上増やす。単なる横密度増加だけで済ませない。
16. **線の可読性**: 1枚刻みの水平線ピッチはDPR 1/1.25/1.5/2で少なくとも1 device pxを維持し、モアレで連続面に潰れない。

### P1: アニメーション

17. **画面内予告**: 正の投入開始後350ms以内に、台上の完成山とは分離したincoming束を1フレーム以上、商戦フィールド内で見せる。
18. **着地連続**: incoming束の最終位置とsettled束の初期位置の差を、中心座標で1 CSS px以内にする。
19. **台と山の同期**: page/rack移送時、台とbanked完成山の相対位置差を1 CSS px以内で維持する。台だけ先に動かさない。
20. **視覚時間と論理時間の分離**: 演出時間を変更しても、所有率、資金、AI行動量、コマンド再充填量を変えない。

### 必須スナップショット行列

各コミットで次の18静止画と、各viewportの正の投入33ms連続フレームを比較する。

- viewport: 390x844、844x390、1440x900
- DPR: 1、1.25、1.5、2
- amount: 0、少量、1page手前、1page完成、bank移送中、bank後
- side: playerのみ、enemyのみ、左右同額、左右非対称
- state: 操作受付中、incoming、コマンド窓、AI投入、決着直前、資金0

最低限の画像差分だけで合格にせず、次の構造値も出力する。

- 台、active、banked、incoming、人物の各マスク面積
- 各マスクのバウンディングボックス
- 台と最前列コインの接触／重なり量
- 人物による台・コインの遮蔽率
- フレーム間のsettled面積変化率
- 左右ミラー誤差
