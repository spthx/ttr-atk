# 『ロマンシング サ・ガ3』トレード・ピクセル研究

- 調査日: 2026-08-22
- 対象: SFC版公開映像の資金投入フレームと現行Canvas2D実装
- 用途: コイン、18アンカー、台座、落下、縦横画面の再現基準
- 数値正本: [`rs3-trade-regression-baseline.json`](./rs3-trade-regression-baseline.json)

この資料は、原作映像を「雰囲気」で参照せず、表示ピクセルから再利用可能な比率へ落とすための台帳である。公開動画はSFC実機の生フレームではなく、拡大・録画・YouTube再圧縮を通っている。そのため絶対ドット数をROM内部座標と断定せず、同一フレーム内の比率を優先する。

## 1. 証拠と方法

主資料は[SFC第一部 02:26.632](https://www.youtube.com/watch?v=N48kVbGG2tE&t=146s)の落下中と、02:28.091前後の着地後。ブラウザが報告した動画ストリームは640×360で、監査時は全画面へ拡大して比較した。

- **O — 観測:** 画面から直接読める形・順序
- **M — 測定:** 再生画像上のピクセル、比率、時間
- **I — 推論:** 可変画面へ移植するための実装値
- **U — 未確認:** ROM、60Hz無加工キャプチャ、原音が必要な項目

第三者動画のフレーム自体はリポジトリへ複製せず、URL、時刻、測定値だけを残す。実装側の監査画像は`docs/evidence/`へ保存する。

## 2. 今回確定した形

### 2.1 金貨素材の見える範囲

現行PNG全体は2106×747。α=128以上の不透明bboxは次である。

```text
x=135, y=167, width=1837, height=397
visible aspect = 1837 / 397 = 4.627204...
```

旧実装は透明余白を含む1847×710を1枚として縮小していた。見える金貨は同じでも、段間隔と接地計算だけが透明余白分ずれ、最低束が原作より細長くなる原因だった。現在はα=128 bboxを直接cropし、見える輪郭と幾何計算を一致させる。

### 2.2 最低束

- **M:** SFC着地束の見える高さは、束幅の概ね0.78〜0.95倍。中央値目標0.86。
- **O:** 安定状態で薄い1枚を残さず、上面・側面・水平仕切りを持つ短円柱として見せる。
- **I:** 1 logical unitは最低8枚。1枚のvisible heightと7段のstepを合わせ、束高/束幅を0.82〜0.90へ固定する。
- **I:** `layerStep = clamp(visibleCoinHeight × 0.43, 1.5, 5.6)`。

### 2.3 18アンカーの投影

- **O:** 奥から`[4,5,5,4]`。
- **M:** 同一列の横pitchは束幅の約0.95〜1.10倍。移植目標1.05。
- **M/I:** 原作は物理的な台上座標より奥行きを誇張する。台座全高を1としたrow baseは、移植値として`[-0.62,-0.20,0.22,0.64]`を採用する。
- **O:** この誇張により18束だけで階段状のピラミッドが成立し、後方束が前方束の後ろに浮いて見えない。
- **O:** 左右は同じ投影の鏡像。

旧値`[0.34,0.44,0.54,0.64]`は奥行き範囲が台座高の0.30しかなく、18束が低い直方体へ潰れていた。新値は後列から前列まで1.26台座高を使い、SFCの疑似立体を再現する。

### 2.4 台座

- **M:** 台座幅は束幅のおよそ5.8〜7.2倍。目標6.5。
- **I:** 実装も6.5へ統一し、以前の可変画面都合の7.45を廃止した。
- **O:** 食器の皿ではなく、上面楕円と縦筋のある厚い低円柱。
- **O:** 前列の根元は前壁で隠し、背景の水平ギャップを許さない。

### 2.5 落下と最終フレーム

- **I:** 空中3姿勢と正確な着地1姿勢、進捗集合`{0, 1/3, 2/3, 1}`。
- **I:** 隣接laneのdelayは`0 / 0.08 / 0.16`。
- **I:** 30fps・165msで各姿勢を最低1フレーム露出させる。
- **P0修正:** active列は静止キャッシュから除き、落下中だけ`before + incoming`を動的描画する。進捗1では両者を重ねず、通常のsettled描画と同じ`after`山を1回だけ描く。

これにより、着地フレームだけ半透明輪郭が二重化して暗くなる問題と、次フレームで山の輪郭が変わる問題を同時に防ぐ。

## 4. 回帰契約

`npm run check:capital-contact`は次を検査する。

1. PNGを実際にdecodeし、金貨α=128 bboxが`135,167,1837,397`から変わらない。
2. 18アンカーと`[4,5,5,4]`、row base、横pitchを数値固定する。
3. 最低束の束高/束幅が0.82〜0.90。
4. 前壁とのdevice-pixel gapが1px以下で、根元が最低1pxは隠れる。
5. DPR 1/1.25/1.5/2で接地を維持する。
6. 空中3姿勢＋着地を30fps・165ms内で露出する。
7. active列を静止キャッシュから外し、最終フレームを`after`山1回へ置換する。
8. 1ページ9波×165ms＝1.485秒。

## 5. まだ原作認証できないもの

- **U:** SFC ROM内の実座標、OAM順、スプライト枚数。
- **U:** 60Hz無加工フレームでの姿勢数。現在の3+1姿勢は公開動画と30fps移植に基づく実装契約。
- **U:** YouTube拡大前の正確な1ドット輪郭と色番号。
- **U:** 台座の縦筋周期が原作スプライトと同周期か。
- **U:** 金貨上面のハイライト形状を原作paletteへ完全一致させる値。

新しい正規キャプチャを得た場合は、原画像を直接製品素材へ流用せず、測定値だけをO/M/I/U付きでこの資料とJSONへ反映する。
