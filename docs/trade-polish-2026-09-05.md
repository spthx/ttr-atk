# 2026-09-05 コインの連続投入と処理負荷の改善

基準commit: `242b44b`。現行fan版の品質改善であり、販売版の素材交換・権利確認・対応機での出荷試験は別途必要。

## 原作との差と変更

[SFC動画 cN6LA6pgznU、300.15〜301.65秒](https://www.youtube.com/watch?v=cN6LA6pgznU&t=300s)の保存済み映像からフレームを再抽出した。画面では短い円柱束が少数ずつ順に落ち、異なる高さに次の束が重なっている。従来の本作は列ごとに小さい高さ差を同時投入し、全面が伸びる見え方になっていた。

今回は18アンカーへ2個ずつ、最大6列の重なった飛行として配る。飛行は330ms、通常の全体は既存の1,485msを保持。1束が32論理層を超える巨額だけ複数巡へ分け、最大144波（23.76秒）で同じ最終枚数を積む。これにより巨大な一本柱の空中落下や、空台座の先行消失を防ぐ。前中央から既存の配置順をたどり、空中の束・着地した束・これから出る束を分ける。波が切り替わっても各束の飛行時刻が連続する。

これらの数値は映像を参考にした実装判断。ROM内部の座標・命令・60Hzの正確なtickを解析したという主張ではない。参照映像自体は製品素材へ入れない。完成山の形、最低8枚の短い束、皿の接地、過積載の共通下降、一枚刻みは維持する。

## 根本的な処理削減

- 柱を128px相当の帯へ分け、画面に見える帯だけを作る。中間の帯は総高さが変わっても再利用し、見えない長柱の画像を生成しない。
- 飛行の段階・山の配置・スクロール量が同じなら完成盤面を再合成しない。所有率だけが変わる場合は安価な背景と既存盤面の合成だけを行う。
- 画面サイズによる列配置とテーマ識別値を再利用。描画loopを所有率の更新ごとに破棄・再起動せず、必要時に起動する。
- 開発サーバーはtmp・dist・public/gameを監視対象から外す。隔離buildの展開だけで進行中のテスト画面を再読み込みしていた問題を解消する。
- 列高の計算は最大9,216回の加算から18列＋余りの計算へ。9,217通りの入力で旧配置との完全一致を検査。
- コマンド再充填量の算出のためだけに古い全アニメーションを構築していた処理を、フレーム数の計算へ変更。288条件の旧式との一致を検査する。
- 巨額で演出時間が伸びたときの1未満の補正倍率も、実際に存在する演出frameだけで選ぶ。未使用frameの既定値1が補正を潰していた受け取り側を修正した。
- Appの操作関数・propsを安定させ、準備度計算を相手とモードごとに共有。商戦中は背面の市場・装備・企業連合などへ親の更新を流さず、終了時に最新状態へ戻す。背面の独立した内部timerを一律停止したという意味ではない。
- 保存400ms、収益1秒、結果確定時の即時保存は保持。保存失敗時の再試行と最新の状態を参照する操作関数を検査した。

## 測定の読み方

同じPC・隔離Edge guest/headless・1190×276の描画面・DPR2で、実際の投入timelineを60Hz相当で5回サンプリングした。これはCPU呼出と描画命令の比較であり、GPU完了時間、スマホFPS、電池や発熱の保証ではない。測定開始直後のコンパイル・バックグラウンド負荷でCPU値が揺れるため、削減量は命令数と保持画像量を主な指標にする。

| 条件 | 変更前のdrawImage合計 | 変更後 | 描画省略frame / 545 |
| --- | ---: | ---: | ---: |
| 初回700 / 相場2000 | 46,917 | 15,825 | 340 |
| 終盤30億 / 相場60億 | 57,287 | 22,687 | 310 |
| 巨大4兆 / 相場60億 | 比較から除外 | 7230サンプルで521,436 | 3545 / 7230 |

巨大投入は長い束を小分けにして演出時間を増やしたため、命令の総数を同じ時間の比較として扱わない。保持する柱画像cacheは33,417,472 → 5,767,168 bytes。全体cacheの上限16/32MiBと64項目は引き続き適用する。GPUの複製やブラウザ全体のメモリはこの数字に含まない。

App単独の検査では、同一文脈の準備度3巡が69→23回、背面に覆いがある間の親更新600回に対する背面の更新受け入れは0。これらは再現用の部品試験であり、実ゲーム全体のfps測定とは区別する。

## 回帰・実画面検査

- 旧getCapitalColumnHeightsと0〜9,216の全入力が一致。
- 各波の境界2,380件（3画面比×4DPR×通常・終盤・巨額、99波の端数ケース）でRGBA差分0。最終着地の1e-7ms以内の丸め誤差も吸収する。
- 従来の着地84件で差分0、皿と根元の共通下降12条件で一致率99%以上。
- 2個ずつの発射、最大6列の重なり、同じ束の連続時刻、最終枚数の保存、command rechargeを検査。
- `scripts/profile-trade-scene.mjs`が実投入timelineを計測、`scripts/verify-authored-rolls.mjs`が境界比較と動画を生成する。
- `scripts/live-trade-qa.mjs`で新規初戦、回転、結果確定と復帰を実操作する。保存値の注入は使わない。
