# 難易度進行・敗北学習設計

## 1. 基本方針

進行するほど敵の予算・押込量だけを増やすのではなく、プレイヤーが扱う選択肢、ビルドの個性、資源を使う順序、状況に応じた組み直しを増やして難易度を上げる。

本作の難易度曲線は次の一文を正本とする。

```text
通常＝会社を育てる
アライアンス＝仲間を増やす
零式＝ビルドを理解する
絶＝戦術を完成させる
酷＝完成した戦術を崩され組み直す
```

終盤の難しさは、演出待ち中の連打、見えない入力受付、短すぎる反射神経テストでは作らない。資金、人脈、LIMIT BREAK、SYNERGY、アビリティ、外部アライアンスを「今使うか」「次の敵行動や査定まで温存するか」の判断で作る。

## 2. 全段階共通の設計原則

### 2.1 数値調整の優先順位

調整は次の順番で検討する。

1. 選択肢に異なる役割を持たせる。
2. 敵の予兆と対処方法を対応させる。
3. 二つ以上の資源が競合する判断を作る。
4. 失敗後に別の準備・順序を試せるようにする。
5. 最後に必要最小限の敵予算、押込量、回復量を調整する。

敵予算の一律倍率、敵AIの一律高速化、プレイヤー資金の一律弱体化だけで段階差を作ってはならない。

### 2.2 公平な難しさ

- 脅威は着弾前に名前、対象、必要な対処を読める。
- 演出とコイン積載中にゲーム時計が止まる仕様を利用し、入力連打を要求しない。
- 判断可能時間は実際のゲーム時計で確保する。
- 正しい対処が複数ある場合は、どれを選んだかで後半の資源状況が変わる。
- 初見殺しは一度の学習で攻略情報へ変わる。
- ランダムだけで敗北を確定しない。
- UIを読めないこと、ボタンが押しにくいこと、テロップが重なることを難易度に含めない。

### 2.3 資源の役割

|資源|今使う価値|温存する価値|
|---|---|---|
|自社資金|確実な直接出資、反転契約の小口消費、査定署名|勝利後の経営、酷の第二査定、最後の一押し|
|人脈|自社資金を減らさず山を作る|共通減衰前の高倍率を危険局面へ残す|
|外部アライアンス|相場75%固定の大きな一回支援|後半の回復、反撃、査定前の所有率確保|
|LIMIT BREAK|大きな所有率回復・決定打|強制清算後、絶の瀕死局面、酷の再構築|
|SYNERGY|ビルド固有の圧力と継続効果|追い風、敵の無敵終了、資金回復との同時使用|
|防御アビリティ|大技を受けて戦術を維持|強制清算や敵LBなど、より危険な着弾への備え|

零式では、人脈の個別支援は1戦18回、LIMIT BREAKは1戦1回を上限とする。防御を崩すために使うか、強制清算後の反撃へ残すかを選ばせ、再充填したLBの連打で温存判断を消さない。絶は人脈を8回、LIMIT BREAKを1回までに絞り、8回の支援を予告へ割り当て、開幕防御を崩すか強制清算後へ残すかを完成させない限り、支援波やLBの反復だけでは押し切れないようにする。高難度記録戦では個別の離反が通常進行へ残らず、支援先一覧での反復選択は実質的な最適解が固定されるため、人脈ボタン1回で使用回数の少ない有力先へ自動配分する。これにより「誰を毎回押すか」という手数を除き、「8回をいつ切るか」という戦術だけを残す。さらに108秒の終極査定を明示し、敵予告・着弾演出中は商戦と査定が停止する。強制清算の着弾時は投資パネルへ自動で戻し、絶では4秒間、自社だけが最初の反撃を選べるようにする。難易度を反射速度や操作不能中の継続圧力ではなく、予告前に何を準備し、どの資源を温存したかで作る。資源枯渇後の受動収入待ちは有限査定で防ぐ。直前の実機標本で見られた残り8〜11秒の受動的な押し切りは落とし、予告対応が噛み合った残り86秒の攻略余地は残す。高難度では自社・人脈・LB・敵防衛の資金積載と味方スキルをすべて短縮演出にして、コイン山の成長と着弾を残したまま待ち時間だけを抑える。酷は第二査定の再構築を主眼とするため、この回数制限を一律適用しない。

すべてを開幕から順番に押すだけで最適解になる場合、難易度設計が成立していない。

## 3. 段階別の学習契約

### 3.1 通常編――会社を育てる

学ばせること:

- 安い事業・契約から毎秒収益と人脈を増やす。
- 自社資金だけでなく、支援元と事業連携を育てる。
- 勝利時の残金と次の都市への準備を考える。
- 風、リキャスト、敵の残予算を順番に理解する。

難易度の作り方:

- 都市ごとに一つずつ新しい判断要素を追加する。
- 都市ボスは、その都市までに学んだ要素を二つ組み合わせる。
- ソリューション・ナインは通常編の卒業試験だが、零式用の完成ビルドまでは要求しない。
- 十分に育成した初見プレイヤーが、敗因を理解して1～2回の再挑戦で越えられる形を目標にする。

避けること:

- 収益待ちだけを要求する進行壁。
- 取得順の正解が一つしかない状態。
- 通常終盤で高難度専用の温存手順を説明なしに要求すること。

### 3.2 アライアンス――仲間を増やす

学ばせること:

- 一戦一回の相場75%支援を、どの局面へ置くか。
- 人脈の共通減衰と、外部アライアンスが減衰外である違い。
- 協力先・公的後援・事業連携の役割差。

難易度の作り方:

- 単純な追加資金ではなく、加入する仲間によって得意な局面が変わる。
- 仲間を増やすことで、零式に持ち込めるビルド候補が増える。
- 全アライアンス取得を強制せず、複数の準備経路を認める。

### 3.3 零式――ビルドを理解する

零式の各層は「装備確認」ではなく、特定の判断を学ぶ教材にする。

|層|主な問い|失敗から学ぶこと|
|---|---|---|
|1層|基礎圧力と回復を維持できるか|準備資金・回復・人脈の不足|
|2層|敵防御の前後へ投入を分けられるか|防御中に大技を浪費しない|
|3層|資本反転へ小口・待機・別資源を選べるか|直接出資の順番と契約解除|
|4層|強制清算を防ぎ、着弾後に反撃できるか|防御と反撃資源の二段温存|

シリーズが進むほど同じ層番号の要求を一段深くする。

- 第1編: 一つの対処を理解する。
- 第2編: 二つの対処を順番に実行する。
- 第3編: 風・回復・支援と対処を同時に管理する。

合格形:

- 未準備なら負ける。
- 適切な準備とビルドなら安定して勝てる。
- 3・4層は資源の使いどころを誤ると、十分な総資産でも負ける。
- 敵予算だけを見て同じ操作を繰り返す攻略にならない。

### 3.4 絶――戦術を完成させる

絶は新しいシステムを大量に追加する場所ではなく、零式で学んだ対処を、複数の敵パターンへ崩さず通す場所にする。

- 開幕と瀕死で異なる敵AUTOパターンを読む。
- 人脈・LB・SYNERGY・直接出資の順序を戦闘全体で設計する。
- 一つの万能手順ではなく、敵パターンに合わせて一部を入れ替える。
- 序盤で資源を使い切れば瀕死局面で負ける。
- 温存しすぎれば序盤の圧力に負ける。

合格形:

- 回復なし、準備不足、判断遅れの大半は敗北する。
- 完成したビルドでも敵パターンを無視すれば負ける。
- 何を温存し、どの敵行動に合わせたかをプレイヤーが説明できる。

### 3.5 酷――戦術を崩され組み直す

酷は単なる絶の高倍率版にしない。プレイヤーが完成させた戦術を第一宣告で崩し、残した資源から別の勝ち筋を組み直させる。

- 第一宣告前: 使いすぎず、ただし10%へ落とされる前提で必要な圧力を作る。
- 回復区間: 所有率50%へ戻す速度と、第二査定用の資源温存を両立する。
- 第二査定: 所有率75%以上と、査定中の自社直接出資10%を満たす。
- 査定後: 残った敵資本へ最後の戦術を再構成する。

人脈・LB・SYNERGY・外部アライアンスだけでは直接出資署名を満たせない現行仕様を明示し、初回失敗後は「所有率不足」「直接出資不足」「両方不足」を分けて伝える。

合格形:

- 絶の固定ローテーションをそのまま使うと崩れる。
- 第一宣告前、回復、査定の三段階で資源配分を変える必要がある。
- 回復なし・2秒程度の判断遅れでも常勝する状態は再調整対象とする。
- 正しい再構築ならランダムに左右されず突破できる。

## 4. 敗北を次の攻略へ変える表示

### 4.1 failure report

敗北時は一つの総評だけで終わらせず、実戦データから主原因を一つ、必要なら副原因を一つ選ぶ。

```ts
type BattleFailureCause =
  | 'insufficient_preparation'
  | 'spent_key_resource_early'
  | 'direct_investment_reversed'
  | 'mitigation_missing'
  | 'recovery_failed'
  | 'ownership_requirement_failed'
  | 'direct_signature_failed'
  | 'support_decay_mismanaged'
  | 'attrition_lost';

interface BattleFailureReport {
  primaryCause: BattleFailureCause;
  secondaryCause?: BattleFailureCause;
  evidenceText: string;
  nextAttemptText: string;
}
```

### 4.2 表示規則

402×874で結果画面を過密にしない。

1. 見出し: 敗因を短い一文で表示する。
2. 根拠: 実測値を一行で表示する。
3. 次の一手: 次回変える行動を一行で表示する。

例:

```text
敗因: 終極資本査定までに自社資金を使い切った
根拠: 所有率78.2% / 査定中の直接出資4.0%（必要10%）
次の一手: 第一宣告後まで相場6%分以上の自社資金を残す
```

禁止:

- 「もっと強くなろう」「順番を見直そう」だけの抽象助言。
- プレイヤーが実行していない行動を敗因として断定する。
- 内部変数名や未公開の敵AI条件を表示する。
- 一度に三つ以上の改善を要求する。

## 5. コイン・音・山を進行報酬にする

進行報酬は数値だけでなく、動かす資金の規模を視覚・音響で実感できるようにする。

- 通常序盤: 少数の束で、投入と所有率移動の対応を覚える。
- 通常終盤・アライアンス: 横幅とpacket継続時間が増え、仲間を増やした成果を見せる。
- 零式: 敵味方の大口が交互に積まれ、山の押し合いを読む。
- 絶: 大量packetと固定台帳の桁上昇を同期し、戦術完成の総力感を出す。
- 酷: 第一宣告後も山を安易に消さず、崩された所有率と残る資本の緊張を両立する。

大量感を増やす場合も、金額比例DOM、物理演算、画面を覆う金額floaterを使わない。固定上限rendererと決定論的timelineを維持する。30/60fpsで絵を減らさない。

## 6. 調整ループ

各変更は主要因を1～2個までに限定し、次を繰り返す。

1. その段階で学ばせる判断を一文で定義する。
2. 敵ギミック、プレイヤー対処、敗北表示を一組で実装する。
3. 決定論シミュレーションで準備あり／なし、回復あり／なし、判断遅れを比較する。
4. 402×874・30fpsの完全新規通しで実際の画面と操作を確認する。
5. FF14＆ロマサガ3ファンが、敗因と次の改善を説明できるか確認する。
6. 数字だけの壁、正解一択、過剰な待ち、UI起因の敗北があれば戻す。
7. P0/P1がなければ次の段階へ進む。

自動勝率だけで調整を確定しない。シミュレーションは極端な崩壊と回帰を見つけるために使い、最終判断は人間が「何を見て、何を温存し、なぜ勝敗が変わったか」を説明できることに置く。

## 7. 監査表

各通しで次を記録する。

|段階|準備|使用順|温存した資源|敗因|次回変更|結果|
|---|---|---|---|---|---|---|
|通常終盤|資金・人脈数・装備|直接／人脈／LB／SYNERGY|残資金等|具体的原因|一つの変更|勝敗・時間|
|アライアンス|協力先|支援を使った局面|一回支援|具体的原因|一つの変更|勝敗・時間|
|零式各層|ビルド|ギミック対処順|反撃資源|具体的原因|一つの変更|勝敗・時間|
|絶各pattern|完成戦術|開幕／瀕死順|終盤資源|具体的原因|一つの変更|勝敗・時間|
|酷各phase|再構築案|第一宣告前／回復／査定|直接署名・LB等|具体的原因|一つの変更|勝敗・時間|

## 8. 完了条件

- 通常終盤から酷まで、段階ごとの学習目的をプレイヤーが区別できる。
- 零式は未準備なら負け、準備とビルド理解で勝てる。
- 零式4層、絶、酷は油断・誤った温存判断で十分な資産があっても負ける。
- 敗北画面から次に変える行動が一つ以上具体的に分かる。
- 同じ敵へ再挑戦した時、その変更が勝敗または戦況へ反映される。
- 難しさの主因が連打、演出待ち、読めないUI、一律数値倍率になっていない。
- コイン、音、山の成長が進行に伴う経済圏の拡大を表現する。
