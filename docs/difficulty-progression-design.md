# 難易度進行・敗北学習設計

## 1. 基本方針

進行するほど敵の予算・押込量だけを増やすのではなく、プレイヤーが扱う選択肢、ビルドの個性、資源を使う順序、状況に応じた組み直しを増やして難易度を上げる。

本作の難易度曲線は次の一文を正本とする。

```text
通常＝会社を育てる
アライアンス＝仲間を増やす
零式＝ビルドを理解する
絶＝戦術を完成させる
酷＝完成した戦術を崩され組み直す
幻＝既知の零式へ絶相当の基礎圧で連続適応する
```

終盤の難しさは、演出待ち中の連打、見えない入力受付、短すぎる反射神経テストでは作らない。資金、人脈、LIMIT BREAK、SYNERGY、アビリティ、外部アライアンスを「今使うか」「次の敵行動や査定まで温存するか」の判断で作る。

挑戦前の戦力は、競合を`防衛力100`へそろえ、`手元資金＋人脈＋外部協力＋SYNERGY／LIMIT BREAK＝動員力`として示す。「自己資金」に保有企業の価値を混ぜず、現金は手元資金、取得済み企業は人脈、今回まとめて使える見込みは動員力と呼び分ける。内部AI値・実額・判定比率は詳細へ退避し、固有ギミック、離反、操作可否など判断を変える情報は伏せない。

## 2. 全段階共通の設計原則

### 2.1 数値調整の優先順位

調整は次の順番で検討する。

1. 選択肢に異なる役割を持たせる。
2. 敵の予兆と対処方法を対応させる。
3. 二つ以上の資源が競合する判断を作る。
4. 失敗後に別の準備・順序を試せるようにする。
5. 最後に必要最小限の敵予算、押込量、回復量を調整する。

敵予算の一律倍率、敵AIの一律高速化、プレイヤー資金の一律弱体化だけで段階差を作ってはならない。

### 2.2 公平な難しさ

- 脅威は着弾前に名前、対象、必要な対処を読める。
- 演出とコイン積載中にゲーム時計が止まる仕様を利用し、入力連打を要求しない。
- 判断可能時間は実際のゲーム時計で確保する。
- 正しい対処が複数ある場合は、どれを選んだかで後半の資源状況が変わる。
- 初見殺しは一度の学習で攻略情報へ変わる。
- ランダムだけで敗北を確定しない。
- UIを読めないこと、ボタンが押しにくいこと、テロップが重なることを難易度に含めない。

### 2.3 資源の役割

|資源|今使う価値|温存する価値|
|---|---|---|
|自社資金|確実な直接出資、反転契約の小口消費、査定署名|勝利後の経営、酷の第二査定、最後の一押し|
|人脈|自社資金を減らさず山を作る|共通減衰前の高倍率を危険局面へ残す|
|外部アライアンス|相場75%固定の大きな一回支援|後半の回復、反撃、査定前の所有率確保|
|LIMIT BREAK|大きな所有率回復・決定打|強制清算後、絶の瀕死局面、酷の再構築|
|SYNERGY|ビルド固有の圧力と継続効果|追い風、敵の無敵終了、資金回復との同時使用|
|防御アビリティ|大技を受けて戦術を維持|強制清算や敵LBなど、より危険な着弾への備え|

通常編の完遂で零式を解放した時点から、モードを問わず人脈支援を1戦ごとの回数制にする。通常・零式・酷・幻は18回、絶・業は8回を上限とし、零式解放前の通常商戦だけは支援元一覧からの個別選択を残す。支援先一覧での反復選択は実質的な最適解が固定され、モバイルでの操作負荷だけを増やすため、回数制では人脈ボタン1回でその時点の最大支援額を出せる有力先へ自動要請する。全体の反復減衰と有限回数は従来どおり適用し、弱い支援先への順送りで投入量やコインの量感だけを落とさない。外部アライアンスは人脈と別の1回発動ボタンに分離し、人脈の選択欄を開かず、人脈の残り回数も消費しない。これにより「誰を毎回押すか」「人脈と外部協力のどちらを選択欄から選ぶか」という手数を除き、有限回の支援をいつ切るかという戦術だけを残す。LIMIT BREAKは通常商戦と同様に、ゲージを全消費した後も再充填すれば同じ戦闘中に再発動できる。防御を崩すか強制清算後の反撃へ回すかは、回数制限ではなく再充填に必要な攻防と発動タイミングで選ばせる。絶は人脈を8回、LIMIT BREAKを1回までに絞り、8回の支援を予告へ割り当て、開幕防御を崩すか強制清算後へ残すかを完成させない限り、支援波やLBの反復だけでは押し切れないようにする。零式・絶・酷商戦は敗北・撤退・報酬0の再戦では通常人脈を保護する一方、初回勝利では攻略報酬の3択配分後に離反と独立危険度を通常進行へ残す。幻・商戦はこの精算規則から除外し、勝敗にかかわらず通常人脈と独立危険度を保護する。さらに108秒の終極査定を明示し、敵予告・着弾演出中は商戦と査定が停止する。強制清算の着弾時は投資パネルへ自動で戻し、絶では4秒間、自社だけが最初の反撃を選べるようにする。猶予終了後は競合の圧力だけを再開し、プレイヤーが反撃を1回入力するまで清算前の自社継続圧力で自動回復させない。難易度を反射速度や操作不能中の継続圧力ではなく、予告前に何を準備し、どの資源を温存したかで作る。資源枯渇後の受動収入待ちは有限査定で防ぐ。直前の実機標本で見られた残り8〜11秒の受動的な押し切りは落とし、予告対応が噛み合った残り86秒の攻略余地は残す。高難度でもコインの資金積載は通常と同じ全量演出を使い、モーション低減を選んだ場合だけ代表波へ圧縮する。味方スキルのカットインは高難度向けに短縮して、判断の待ち時間だけを抑える。

すべてを開幕から順番に押すだけで最適解になる場合、難易度設計が成立していない。

## 3. 段階別の学習契約

### 3.1 通常編――会社を育てる

学ばせること:

- 安い事業・契約から毎秒収益と人脈を増やす。
- 自社資金だけでなく、支援元と事業連携を育てる。
- 勝利時の残金と次の都市への準備を考える。
- 風、リキャスト、敵の残予算を順番に理解する。

難易度の作り方:

- 都市ごとに一つずつ新しい判断要素を追加する。
- 都市ボスは、その都市までに学んだ要素を二つ組み合わせる。
- ソリューション・ナインは通常編の卒業試験だが、零式用の完成ビルドまでは要求しない。
- 十分に育成した初見プレイヤーが、敗因を理解して1～2回の再挑戦で越えられる形を目標にする。

避けること:

- 収益待ちだけを要求する進行壁。
- 取得順の正解が一つしかない状態。
- 通常終盤で高難度専用の温存手順を説明なしに要求すること。

### 3.2 アライアンス――仲間を増やす

学ばせること:

- 一戦一回の相場75%支援を、どの局面へ置くか。
- 人脈の共通減衰と、外部アライアンスが減衰外である違い。
- 協力先・公的後援・事業連携の役割差。

難易度の作り方:

- 単純な追加資金ではなく、加入する仲間によって得意な局面が変わる。
- 仲間を増やすことで、零式に持ち込めるビルド候補が増える。
- 全アライアンス取得を強制せず、複数の準備経路を認める。

### 3.3 零式――ビルドを理解する

零式の各層は「装備確認」ではなく、特定の判断を学ぶ教材にする。

|層|主な問い|失敗から学ぶこと|
|---|---|---|
|1層|基礎圧力と回復を維持できるか|準備資金・回復・人脈の不足|
|2層|敵防御の前後へ投入を分けられるか|防御中に大技を浪費しない|
|3層|資本反転へ小口・待機・別資源を選べるか|直接出資の順番と契約解除|
|4層|強制清算を防ぎ、着弾後に反撃できるか|防御と反撃資源の二段温存|

シリーズが進むほど同じ層番号の要求を一段深くする。

- 第1編: 一つの対処を理解する。
- 第2編: 二つの対処を順番に実行する。
- 第3編: 風・回復・支援と対処を同時に管理する。

合格形:

- 未準備なら負ける。
- 適切な準備とビルドなら安定して勝てる。
- 3・4層は資源の使いどころを誤ると、十分な総資産でも負ける。
- 敵予算だけを見て同じ操作を繰り返す攻略にならない。

### 3.4 絶――戦術を完成させる

絶は新しいシステムを大量に追加する場所ではなく、零式で学んだ対処を、複数の敵パターンへ崩さず通す場所にする。

- 開幕と瀕死で異なる敵AUTOパターンを読む。
- 挑戦ごとに選ばれた開幕／瀕死パターンと具体的な対処を戦前ブリーフィングへ出し、ランダムだけで敗北を確定させない。
- 安定攻略の準備例は、開幕AUTOパッセ、瀕死AUTOリビングデッド、手動ぶんどると短時間防御、LB III。別ビルドも許すが、現在のAUTO・LB充填・不足準備は挑戦前に読めるようにする。
- ブラックナイトが割れずに終了した場合は残った障壁量を敗因へ出し、「開始直後ではなく危険予告へ合わせる」という次の一手を示す。
- 人脈・LB・SYNERGY・直接出資の順序を戦闘全体で設計する。
- 一つの万能手順ではなく、敵パターンに合わせて一部を入れ替える。
- 序盤で資源を使い切れば瀕死局面で負ける。
- 温存しすぎれば序盤の圧力に負ける。

合格形:

- 回復なし、準備不足、判断遅れの大半は敗北する。
- 完成したビルドでも敵パターンを無視すれば負ける。
- 何を温存し、どの敵行動に合わせたかをプレイヤーが説明できる。

### 3.5 酷商戦――戦術を崩され組み直す

`酷商戦`（サブタイトル`酷-もう1人のわたし`）は単なる絶の高倍率版にしない。プレイヤーが完成させた戦術を第一宣告で崩し、残した資源から別の勝ち筋を組み直させる。

- 第一宣告前: 使いすぎず、ただし10%へ落とされる前提で必要な圧力を作る。
- 回復区間: 演出停止時間を除く10秒以内に所有率50%へ戻す速度と、第二査定用の資源温存を両立する。未到達でも第二査定を強制開始する。
- 第二査定: 所有率75%以上と、査定中の自社直接出資10%を満たす。
- 査定後: 残った敵資本へ最後の戦術を再構成する。

人脈・LB・SYNERGY・外部アライアンスだけでは直接出資署名を満たせない現行仕様を明示し、初回失敗後は「所有率不足」「直接出資不足」「両方不足」を分けて伝える。

合格形:

- 絶の固定ローテーションをそのまま使うと崩れる。
- 第一宣告前、回復、査定の三段階で資源配分を変える必要がある。
- 回復なし・2秒程度の判断遅れでも常勝する状態は再調整対象とする。
- 正しい再構築ならランダムに左右されず突破できる。

### 3.6 業商戦：値札のない一株――自分の勝ち筋を読み替える

`業商戦：値札のない一株`は酷商戦踏破後に、幻・商戦と並行して解放する記録専用の最高難度戦である。ものまね師をモチーフに、敵の数字を隠して膨らませるのではなく、プレイヤーが直前に見せた一手だけを「帳簿」に写し取り、その場で別系統へ切り替える判断を要求する。

- 開幕50%から所有率55%・70%・85%・95%へ初めて届いたプレイヤーの有効な一手を、その節目の記録として一件だけ保持する。一つの行動で複数の境界をまたいでも、発生するものまねは次の未解決の節目一回だけとする。
- 記帳した一件を6秒予告し、その場でものまねする。予告に表示された二系統なら完全取消、表示外でも別系統なら50%軽減、同系統または無行動なら有限の写しが100%着弾する。成否を問わず解決後は記録を消去し、通常の攻防へ戻して次の節目を待つ。
- 四件をまとめて保持する帳簿、逆順再生、修正仕訳は設けない。前面UIには常に「いま記憶されている一手」「完全取消できる二系統」「残り回数」だけを示し、過去の手を暗記させない。
- 写しは有限で、同系統を選んでも即死や時間切れを発生させない。失敗は「現在の一手へ何を返したか」として読める形にし、次回は別系統の資源を一つ残すという具体策へ変換する。勝利寸前でも四回のものまねを崩すまでは決着を保留し、偶然の押し切りを防ぐ。
- 競合予算の24%は戦闘開始時に無銘口座へ事前隔離し、四回の写しにだけ使う。これは隠し増資ではなく、最初から上限がある反撃資源である。前面UIは数値の羅列にせず、現在見切られている一手と別系統で崩せることを優先して知らせる。
- 参加費、攻略報酬、勝後精算はすべて0とする。通常資金、所有権、毎秒収益、人脈と独立危険度、持越しLB、通常進行は勝敗・撤退を問わず保護し、勝利時は`karmaCleared`だけを保存する。幻・商戦の現在連勝数も変えない。

業商戦の契約は、「四つの手を覚える」のではなく、「いま一つだけ表示された手を読み、別の資源で返す」を四回繰り返すことである。資源不足で詰ませず、現在の予告を読んで対処すれば必ず打開できる状態を維持する。

### 3.7 幻・商戦――既知の12層へ連続適応する

酷商戦踏破後に解放する、現在連勝数だけを競う記録専用戦とする。挑戦ごとに商戦 零式の3シリーズ×4層、全12層から一つをランダムに選ぶ。

- 抽選された層の予告、資本反転、強制清算、支援プロフィールなど、層固有のギミックをそのまま再現する。
- 引き上げるのは競合の基礎資本と判断難易度だけとし、絶固有の108秒査定、1戦1回のLB制限、人脈8回制限などを追加しない。
- 勝利時は現在連勝数を1増やし、次の相手を抽選する。
- 敗北または戦闘中の能動的な撤退では現在連勝数を0へ戻し、次の相手を抽選する。
- 戦前ブリーフィングを閉じただけなら現在連勝数も抽選済みの相手も維持する。
- 永続保存する戦績は現在連勝数だけとし、最高記録、層別記録、踏破報酬を設けない。
- 参加費、攻略報酬、所有権移転、通常資金の増減、毎秒収益、通常人脈の離反・独立危険度、持越しLBゲージ、他コンテンツの進行を一切変化させない。

合格形:

- どの層を引いても、その零式層で学んだ対処が有効である。
- 絶相当の基礎圧で準備と判断を要求するが、絶や酷の別ギミックを混ぜて初見即死を作らない。
- 連勝中も相手ごとにビルドと資源配分を読み替える必要がある。
- 通常進行の損得ではなく、現在の連勝数だけが挑戦理由になる。

## 4. 敗北を次の攻略へ変える表示

### 4.1 failure report

敗北時は一つの総評だけで終わらせず、実戦データから主原因を一つ、必要なら副原因を一つ選ぶ。

```ts
type BattleFailureCause =
  | 'insufficient_preparation'
  | 'spent_key_resource_early'
  | 'direct_investment_reversed'
  | 'mitigation_missing'
  | 'recovery_failed'
  | 'ownership_requirement_failed'
  | 'direct_signature_failed'
  | 'support_decay_mismanaged'
  | 'attrition_lost';

interface BattleFailureReport {
  primaryCause: BattleFailureCause;
  secondaryCause?: BattleFailureCause;
  evidenceText: string;
  nextAttemptText: string;
}
```

### 4.2 表示規則

402×874で結果画面を過密にしない。

1. 見出し: 敗因を短い一文で表示する。
2. 根拠: 実測値を一行で表示する。
3. 次の一手: 次回変える行動を一行で表示する。

例:

```text
敗因: 終極資本査定までに自社資金を使い切った
根拠: 所有率78.2% / 査定中の直接出資4.0%（必要10%）
次の一手: 第一宣告後まで相場6%分以上の自社資金を残す
```

禁止:

- 「もっと強くなろう」「順番を見直そう」だけの抽象助言。
- プレイヤーが実行していない行動を敗因として断定する。
- 内部変数名や未公開の敵AI条件を表示する。
- 一度に三つ以上の改善を要求する。

## 5. コイン・音・山を進行報酬にする

進行報酬は数値だけでなく、動かす資金の規模を視覚・音響で実感できるようにする。

- 通常序盤: 少数の束で、投入と所有率移動の対応を覚える。
- 通常終盤・アライアンス: 横幅とpacket継続時間が増え、仲間を増やした成果を見せる。
- 零式: 敵味方の大口が交互に積まれ、山の押し合いを読む。
- 絶: 大量packetと固定台帳の桁上昇を同期し、戦術完成の総力感を出す。
- 酷: 第一宣告後も山を安易に消さず、崩された所有率と残る資本の緊張を両立する。
- 幻: 抽選された零式層の資金山と着弾表現を維持し、絶相当へ上がった基礎圧を見た目でも判別できるようにする。

大量感を増やす場合も、金額比例DOM、物理演算、画面を覆う金額floaterを使わない。固定上限rendererと決定論的timelineを維持する。30/60fpsで絵を減らさない。

## 6. 調整ループ

各変更は主要因を1～2個までに限定し、次を繰り返す。

1. その段階で学ばせる判断を一文で定義する。
2. 敵ギミック、プレイヤー対処、敗北表示を一組で実装する。
3. 決定論シミュレーションで準備あり／なし、回復あり／なし、判断遅れを比較する。
4. 402×874・30fpsの完全新規通しで実際の画面と操作を確認する。
5. FF14＆ロマサガ3ファンが、敗因と次の改善を説明できるか確認する。
6. 数字だけの壁、正解一択、過剰な待ち、UI起因の敗北があれば戻す。
7. P0/P1がなければ次の段階へ進む。

自動勝率だけで調整を確定しない。シミュレーションは極端な崩壊と回帰を見つけるために使い、最終判断は人間が「何を見て、何を温存し、なぜ勝敗が変わったか」を説明できることに置く。

## 8. 完了条件

- 通常終盤から幻・商戦まで、段階ごとの学習目的をプレイヤーが区別できる。
- 零式は未準備なら負け、準備とビルド理解で勝てる。
- 零式4層、絶、酷は油断・誤った温存判断で十分な資産があっても負ける。
- 幻・商戦は全12層の固有ギミックを保ったまま基礎力だけが絶相当で、現在連勝数以外の通常データを変えない。
- 敗北画面から次に変える行動が一つ以上具体的に分かる。
- 同じ敵へ再挑戦した時、その変更が勝敗または戦況へ反映される。
- 難しさの主因が連打、演出待ち、読めないUI、一律数値倍率になっていない。
- コイン、音、山の成長が進行に伴う経済圏の拡大を表現する。
